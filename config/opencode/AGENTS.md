# Comment Placement

Place each comment immediately before the smallest code element it describes.

Do not attach a comment to a resource, function, block, or section header when it only explains one attribute, argument, branch, or statement inside it. Put it directly above that line instead. Keep comments concise and avoid duplicating information already evident from the code.

# One file per patch

Unless the users explicitly says to edit in parallel edit ONLY ONE file at a time. Complete each file edit before beginning an edit to another file.
